# Working in this tree

Read `AGENTS.md` as well; everything in it applies.

- Do not stop to say what you are going to do next.  Do it.  When a piece
  of work is finished, start the next one: there is a plan in
  `doc/osprey-progress.ms` and it names the order.  Report what was
  built and what was verified, not what is coming.
- Do not ask for input, confirmation, or a choice between approaches
  until everything the two Osprey sources describe is implemented.
  Decide, build it, test it against a booted kernel, and say plainly in
  the man page and in the commit what is real and what is only
  demonstrated.
- Keep `doc/osprey-progress.ms` current as each piece lands.
